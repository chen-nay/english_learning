# 添加单词、短语和句型

这是本项目的词库维护约定。以后可以直接说：

> 参考 `notebook/ADDING_ENTRIES.md`，加入：新单词、短语或句型列表。

## 默认添加到哪里

**默认添加到 Word Notebook，修改项目根目录下的 `notebook/words.json`。** 本文与单词本数据放在同一个目录下。

只有用户明确要求添加到 **Similar Words**、整理易混词对比组时，才修改 `similarword/similar_words.json`。

所有路径均相对于项目根目录。先读取目标 JSON 和 `index.html` 中对应的渲染逻辑，再按现有格式添加数据。

## 顺序与保留规则

- **本批条目放到 JSON 数组最前面**；同一批按用户提供的顺序排列，新条目和已存在条目混合时也遵守这一顺序。
- 先检查重复，忽略大小写和多余空格。同一词或同一表达已在 Word Notebook 中时，**直接复用原条目，将其从原位置移到本批对应的位置**，不要重复添加，也不要默认重写或补充原内容；仅在用户明确要求修改时编辑内容。
- 同一批列表内也要去重，按首次出现的位置保留一次。不能先保留旧位置，再在前面复制一份。
- 保留所有旧条目；未被本批点名的条目内容和相对顺序保持不变。不用时间字段，也不增加前端排序逻辑。
- 保留用户提供的学习对象。拼写错误可以纠正并说明；需要补齐宾语或接续结构时，在结构和用法中说明。
- 只添加用户提供的内容；补充必要的义项、搭配和例句，不擅自扩展成整批无关词汇。
- 不修改其他频道，不提交、不推送、不部署，除非用户另外要求。

## Word Notebook：共用字段

`notebook/words.json` 是对象数组，一个学习条目对应一张卡片。

| 字段 | 约定 |
| --- | --- |
| `word` | 卡片标题，例如 `oversight`、`add to`、`be capable of doing sth` |
| `type` | 单词为 `word` 或省略；短语为 `phrase`；句型为 `pattern` |
| `phoneticUs` | 美式 IPA，包含两侧 `/`；不要填英式音标 |
| `pos` | 英文词性或结构标签，例如 `n.`、`v. + prep.`、`be + adj.` |
| `summary` | 简短中文释义，供紧凑卡片直接展示 |
| `note` | 整条内容的记忆或使用提示，没有必要提示时可省略 |
| `senses` | 至少一个义项，最值得先学的义项放在第一位 |
| `sources` | 核对音标、词义和语法的来源，格式为 `[{"label":"Cambridge","url":"实际词条链接"}]` |
| `pronunciationText` | 可选，指定自然朗读的文本；如把标题中的 `sth` 展开为 `something` |

来源链接保存在数据中供后续核对，**不要重新在卡片或弹窗中显示 Sources、学习示例免责声明等页脚**。

## 单词：按义项填写

参考 `notebook/words.json` 中的 `oversight`、`recall` 等现有词条。

每个 `senses` 元素包含：

- `meaning`：该义项的中文含义。
- `grammar`：词性、可数性或语体说明，例如 `n. [U]`。
- `definition`：简短中文解释。
- `phrases`：常见搭配，格式为 `[{"en":"英文搭配","cn":"中文含义"}]`，至少一条。
- `sentence`：一条完整的原创双语例句，格式为 `{"en":"英文句子","cn":"中文翻译"}`。
- `synonyms`、`antonyms`：格式同 `phrases`，按当前义项选择，不混用其他义项的近反义词。
- `synonymNote`、`antonymNote`：解释使用限制；没有自然对应词时使用空数组，并在说明中如实解释。
- `phoneticUs`：可选；不同词性读音不同时，在对应义项标出读音，如 `recall` 的名词。

多义词按常见含义分别组织。例如 `oversight` 的“疏漏”和“监督”各自对应词组、例句和近反义表达。优先覆盖常用义项，不必堆砌所有罕见释义。

## 短语与句型：突出结构和用法

参考 `add to`、`distract from`、`be capable of doing sth`、`attempt to` 等现有词条。

- **Phrase**：作为整体学习的短语或搭配，例如 `add to`、`call for`。
- **Pattern**：强调可替换位置和接续规则的句型，例如 `be capable of doing sth`、`attempt to`。
- 分界有交叉时，按本条内容的学习重点归类，避免重复收录。

每个 `senses` 元素包含：

| 字段 | 内容 |
| --- | --- |
| `meaning` | 当前义项的中文含义 |
| `grammar` | 简短语法说明，无需说明时可为空字符串 |
| `definition` | 当前义项的中文解释 |
| `structure` | 可替换的结构，例如 `distract someone from + noun / doing sth` |
| `phrases` | 常见的实际用法，使用双语 `en` / `cn` 对象数组，至少一条 |
| `sentence` | 一条完整的原创双语例句，使用 `en` / `cn` 对象 |
| `usageNotes` | 中文提示字符串数组，解释介词、不定式、动名词、宾语、时态或易错点 |
| `relatedExpressions` | 可选，值得对照的表达，使用双语 `en` / `cn` 对象数组 |
| `relatedNote` | 可选，说明相关表达在含义、语气或结构上的区别 |

**短语和句型不强制填写 `synonyms`、`antonyms`。** 有学习价值的近义、反向或相近结构，才放入 `relatedExpressions`；没有就省略，不为了填栏目凑词。

结构必须可直接用于造句，明确名词、动词原形、`doing`、从句和宾语的位置。`sth`、`sb` 是占位符，必要时在提示中解释；朗读时使用 `pronunciationText` 展开缩写。美式音标应对应实际朗读文本。

## 内容质量

- 核对可靠词典中的美式读音、常见义项、搭配及接续规则，例如 Cambridge、Oxford、Merriam-Webster；保存实际查到的词条链接，不编造核对结果。
- 短语的音标按常见美式读法填写，注意弱读；不要把由单词读音组合的标音声称为词典提供的整句音标。
- 每个义项提供常用搭配及完整例句；英文与中文含义对应。优先采用自然的开发、工作或日常场景。
- 例句尽量原创，不大段复制词典内容。语法对照要准确，不制造不自然的错误例句。
- 近义不代表任意替换；反向概念不一定是严格反义词，应在提示中说明。
- 界面标签使用英文，学习内容保留中文解释和翻译。普通添加词条不需要改页面设计。

## 保持现有交互

- 单词的紧凑卡片默认显示音标、简短中文释义、第一义项的首个搭配和例句。
- 短语与句型的紧凑卡片默认显示音标、中文释义、第一义项的结构和例句。
- **More details 打开独立弹窗**，显示完整内容，不让原卡片向下伸展。
- 按 **Esc** 或点击 **Close** 关闭，焦点回到原按钮；单词与例句可以朗读。
- 不新增频道、筛选器或时间字段，除非用户明确要求。

## 用户明确要求添加 Similar Words 时

目标改为 `similarword/similar_words.json`，以已有对比卡为模板：

- 每组包含 `category`、`title`、`note`、`words`，建议 2–5 个有明确比较关系的词。
- `category` 只能使用现有值：`spelling`（拼写接近）、`meaning`（工作用词）、`concept`（专业概念）、`family`（同词根）或 `suffix`（相似词缀）。
- 每个词填写 `en`、`phonetic`（美式）、`pos`、`cn`、`example`、`exampleCn`。
- 标题说明比较对象，`note` 点出区别；不要把随机词汇凑在一组。
- 新组放在数组前面，同组内避免重复；同一个词可以出现在不同且有价值的比较关系中。
- 注意：此频道的页面先按现有类别顺序渲染，再按数组顺序展示该类别内的卡片。因此放在 JSON 最前面的新组会优先出现在**所属类别**内；不要擅自改变分类布局。
- 保持逐词揭示、整组显示/收起的自测交互。

## 完成前检查与交付

1. 确认 JSON 可解析、字段完整、没有意外重复、原内容保留、本批条目按顺序置顶；已存在条目仅移动且全数组只保留一份。
2. 确认 `senses`、`phrases` 非空，例句英中对应，新增短语和句型有 `structure` 与 `usageNotes`。
3. 检查标题中的占位符不会被当成缩写逐字母朗读。
4. 按实际条目数量更新 README 中对应频道的统计；不修改无关文案和资源。
5. 数据添加无需更新 `source.json`，也不需要增加依赖或测试框架。若修改渲染逻辑，应检查卡片、详情弹窗、关闭及朗读交互。
6. 检查 `git diff --check`，最后简短说明新增数量、已有条目置顶数量、当前总数及本地查看方式；已有条目置顶不计入新增数量。

最基本的数据解析检查：

```bash
python3 -m json.tool notebook/words.json > /dev/null
```

若本地静态服务尚未启动，在项目根目录运行：

```bash
python3 -m http.server 9001 --bind 127.0.0.1
```

然后打开 `http://127.0.0.1:9001/`，刷新后进入 Word Notebook。若已有服务，直接复用。
